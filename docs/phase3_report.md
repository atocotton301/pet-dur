# Phase 3 보고 — 백엔드 API (2026-11-25)

## 1. 한 것
- **약물군 소속 테이블** `substance_class_member` 추가. 9개 약물군, 56개 성분. 모두 원문에서 확인했다(Merck/MSD 위주, 1등급 4건). → 이제 사람 약 성분이 "NSAID계" 같은 약물군 병용 규칙에 걸린다.
- **사람 상비약 샘플** 122개 제품(검색어 27개, `data/product_queries.txt`). 85개 제품은 규칙이 있는 성분을 1개 이상 포함한다.
- **SQLite 스키마** `app/schema.sql` (ERD + 약물군 소속), **적재 스크립트** `scripts/load_db.py`(재실행 가능)
  - 물질 179 · 별칭 415 · 독성 규칙 148 · 병용 규칙 97 · 출처 72 · 동물약 14,817 · 영업 중 동물병원 5,268(좌표 WGS84 변환)
  - Phase 2에서 같은 물질이 영어 이름 차이로 갈라졌던 규칙을 합쳤다(조류 PTFE 3건 → 1건 등). 그래서 독성 규칙이 150 → 148건이 됐다.
- **성분 정규화** `app/normalize.py`: `슈도에페드린염산염` → `슈도에페드린`, `아세트아미노펜(미분화)` → `아세트아미노펜` 등
- **API** `app/main.py` (FastAPI, GET만)

| 엔드포인트 | 내용 |
|---|---|
| `GET /species` | 지원 종 6개 |
| `GET /search?q=&species=` | 물질(동의어·오타 허용) + 사람 약 제품(성분별 판정·종합 등급) + 동물약 제품명 |
| `GET /substance/{id}?species=` | 물질 하나의 판정 카드 (등급, 기전, 증상, 대처, 출처, 감수 상태) |
| `GET /product/{item_seq}?species=` | 제품 → 전 성분 → 성분별 판정 → 가장 위험한 등급으로 종합 |
| **`GET /interactions/check?items=p:…,s:…&species=`** | **병용 점검(핵심)**: 항목 쌍마다 성분·약물군 규칙을 조회. 같은 성분이 겹치는지, 규칙 DB에 없는 성분은 무엇인지도 알려준다 |
| `GET /clinics?lat=&lng=` | 반경 10km 안의 영업 중 동물병원을 가까운 순으로 |

## 2. 지킨 원칙 (테스트로 고정)
- 규칙이 없으면 "확인된 정보 없음 — 수의사 상담을 권장합니다". **안전으로 표시하지 않는다.**
- 알려진 성분이 전부 안전이어도 **미확인 성분이 하나라도 있으면 제품 종합은 '정보 없음'**.
- "먹어도 됩니다", "안전합니다" 같은 단정 문구 금지.
- 모든 응답에 "이 정보는 수의사 진료를 대체하지 않습니다."
- 24시·특수동물 여부는 데이터에 없으므로 `is_24h = null`(모름)로 둔다. 이름에 "24"가 있는지만 `name_suggests_24h`로 따로 준다(화면에 쓸지는 미정).

## 3. 테스트 — `pytest tests` → **25개 모두 통과**
종합 등급 조합 6가지, 제품 → 성분 → 종합 등급, 염 표기 성분 연결, 정보 없음 처리, 단정 문구 금지, 동의어(파라세타몰), 오타 별칭(초코렛), 유사도 오타(아세트아미노핀), 제품명 검색, 약물군을 거친 병용(덱시부프로펜 제품 + 카프로펜 → 함께 쓰면 안 됨), 직접 병용(트라마돌 + 플루옥세틴), 규칙 없는 종(토끼)은 '정보 없음', 중복 성분 감지, 미확인 성분 목록, API 5종.

## 4. 실행
```
pip install -r requirements.txt
python scripts/load_db.py          # data/app.db 생성 (data/raw 공공데이터 필요, 없으면 --no-raw)
uvicorn app.main:app --reload      # http://localhost:8000/docs
pytest tests
```

4. 24시 표시 방식(A 표시 안 함 / B "24시(추정)" / C 직접 확인)이 아직 미정이다. Phase 4 화면에서 필요하다.
